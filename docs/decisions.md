# Decisions and deviations from BUILD_INSTRUCTIONS.txt

BUILD_INSTRUCTIONS.txt is the source of truth. This file records where the
team settled an ASSUMPTION or chose to deviate from it. Every PR that relies
on one of these should mention it.

| # | Topic | Instructions say | Decision |
|---|-------|------------------|----------|
| 1 | Resize step (2.8, 7.1) | ASSUMPTION: `RESIZE_STEP = 1` | Confirmed: `RESIZE_STEP = 1`, sizes 8..16. Still a single constant. |
| 2 | Quit in C (3) | Esc quits outside color entry | **Deviation:** Esc only cancels color entry. The C app quits only when the window is closed (`SetExitKey(KEY_NULL)`, since raylib quits on Esc by default). asm `q` still quits. |
| 3 | Replay tokens (12.2) | Lists w e i j k l z y + - c p 1-8 and `t #RRGGBB` | Replay accepts every asm key with the asm meaning: `=` is `+`, uppercase folds to lowercase, `c` clears, `s` writes the PNG to `--out`. The PNG is also written when the script ends. An unknown token is an error that reports the line number. |
| 4 | RARS check (12.3, 12.4) | `java -jar rars1_6.jar a nc p asm/main.asm`, optional in CI | **Fix:** RARS 1.6 exits 0 on assembly errors unless `ae<n>` is given. Use `a nc ae1 p`. The check is **required** in CI and also assembles `asm/smoke/first_pixels.asm` on its own. |
| 5 | first_pixels.asm location (4.2) | `asm/first_pixels.asm` | `asm/smoke/first_pixels.asm` (as 12.3 suggests), so project mode does not see a second `main`. Other stand-alone programs (`key_test.asm`) go there too. |
| 6 | Constants (7.1) | No row-size constant | **Added** `DISPLAY_ROW_BYTES = 512` (`DISPLAY_W * 4`) to both `config.h` and `constants.asm`. RARS `.eqv` is plain text substitution and cannot evaluate `DISPLAY_W * 4`, so the asm needs the value spelled out. Also **added** the display colors `BG_COLOR` (0x303030, from 7.5), `EMPTY_LIGHT` (0xDCDCDC) and `EMPTY_DARK` (0xC4C4C4) so the C window and the asm display draw EMPTY cells identically. |
| 7 | asm file list (4.2) | No `app.asm` | **Added** `asm/app.asm` as the counterpart of `c/src/app.c` (`app_init`, `do_paint`, and later every `do_*` action), so each C file maps onto one asm file with the same function names. |
| 8 | Luminance/cursor color location | Not specified | `luminance_q8` and `cursor_color` live in `grid.c` / `grid.asm` (pure functions, unit-tested without raylib). |
| 9 | Color entry details (2.4) | Not specified | The entry buffer takes any printable ASCII character (0x20..0x7E), up to 7 (`ENTRY_MAX_LEN`, buffer 8 bytes per 7.3); `parse_hex` decides validity on Enter, so `#12345G` can be typed and rejected. Enter always leaves entry mode, valid or not. "Invalid color" stays on screen until the next `t`. |
| 10 | Where `.data` lives (9) | "in this order" | All global state is declared in `asm/main.asm`, in section 9 order. RARS places the main file's `.data` first and every other file's after it in alphabetical order, so this is the only way to pin `grid` at 0x10010000. Modules reference the labels via `.globl`; only constant strings stay in the module that prints them. |
| 11 | asm unit tests (12) | Only manual asm testing | **Added** `asm/tests/test_main.asm`: headless checks of the pure asm functions (same cases as the C tests), run in CI. The modules are passed as extra files on the command line, because RARS refuses to `.include` the same file (`constants.asm`) twice in one assembly. Exit code = failed checks. |
| 12 | Mouse in entry mode (2.4, 2.2, 2.3) | "While in color entry mode, all other shortcuts are disabled" | Mouse clicks count as shortcuts: they are ignored while `entry_mode` is 1 (same gate as the keys). Hit testing is `grid_cell_at` in `grid.c`; it returns 0 for the centering margin and outside the canvas. |
| 13 | asm `grid_cell_at` signature (C step 3) | `grid_cell_at(px, py, ..., int *row, int *col)` with output pointers | asm has no pointers: returns a0 = 1 inside / 0 outside, with row in a1 and col in a2 (a1/a2 unchanged when outside). Uses a 32-byte frame (it saves s8-s11). It is not called by the RARS program (no mouse); it is kept for the function-by-function mapping and tested in `asm/tests/test_main.asm`. |
| 14 | Ctrl combos (2.7, 2.8) | ctrl+delete, ctrl+plus, ctrl+minus | While Ctrl (or Cmd) is held, the C app handles only the clear and resize keys and ignores every other key that frame, so ctrl+arrow and ctrl+w do nothing. `do_resize` returns 0 at the limits (8 and 16) and when the delta is 0. Shrinking clears the cells outside the new size, so growing back does not bring them back until undo exists (step 5). |
| 15 | asm grow key in RARS (step 4) | `+` (or `=`) grows | Both are accepted. In one RARS run, `xdotool key plus` (Shift+=) dropped one of eight presses, which ended at n = 11 instead of 12. The step 4 check uses plain `=` and got an exact frame. This is a test-input issue; the keyboard MMIO itself is fine. |
| 16 | No-op actions and history (10, step 5) | "No-op actions push nothing (... clearing an already-empty grid is allowed to push; keep it simple)" | A no-op pushes nothing: paint or erase on a cell that already has the color, clear on an all-EMPTY canvas, and a resize refused at the limits. Undo and redo never push. Redo of CLEAR and RESIZE calls the same `apply_*` helpers as the actions, so the state is exactly what the original action produced. |
| 17 | Auto-save on paint (2.6, step 6) | "The first time a color is used to paint, it is also saved automatically" | `do_paint` calls the palette save on every paint, even when the cell already had that color. Duplicates are ignored, so this only matters for a color that was pushed out of the ring. Erase never saves EMPTY. |
| 18 | C palette layout and clicks (2.6, 2.2, step 6) | Not specified (C layout is free) | Two columns of four swatches, slot k in column k & 1 and row k >> 1, the same mapping as the asm (7.5). Keys 1..8 and the keypad digits both pick. A left click on a swatch picks it and does not paint the cursor cell; a right click on a swatch does nothing; an empty slot does nothing. |
| 19 | asm palette drawing (7.5, step 6) | 10 x 10 swatches, "dark gray outline" for empty slots | Empty slot: a 1-unit `0x00505050` outline inside the 10 x 10 box. Saved slot: the color fills the box. The current color's swatch gets a 1-unit `0x00E0E0E0` ring just outside the box (it fits in the 3-unit gap between swatches). `draw_palette` first clears the whole palette area to the background, so frames from an old current color disappear. |
| 20 | asm `palette_slot_at` (C step 6) | `*slot` output pointer | Like `grid_cell_at` (row 13): returns a0 = 1 on a swatch with the slot in a1, a0 = 0 otherwise (a1 unchanged). Not called by the RARS program (no mouse); tested in `asm/tests/test_main.asm`. |
| 21 | Palette keys in asm (2.6) | Keys 1..8 | `1`..`8` pick slots 0..7, `p` saves. Both redraw the palette and the preview; a pick also prints `Color set:` on the console, as `t` does. |
